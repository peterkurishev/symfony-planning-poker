## UC-07. Оценка задачи — ⚠️

- [ ] **Свой голос не восстанавливается после перезагрузки страницы.** API не отдаёт участнику его
  собственное значение в активном раунде (только `voted_user_ids`), `myVote` живёт в памяти компонента.
  После обновления страницы карточка не выделена, а повторное нажатие той же карточки перезаписывает
  голос вместо отмены (шаг 4 и сценарий «Отмена голоса»). Нужно поле вроде `my_vote` в
  `ApiPresenter::round()` для текущего пользователя.
- [ ] **«Не проголосовал» в результатах.** Участники без голоса не отображаются в таблице результатов
  (см. UC-08).

Голосование, перезапись, отмена, `vote.cast`/`vote.retracted` без значения, `round.all_voted`
владельцу, 422/403 — ✅.

## UC-08. Остановка оценки — ⚠️

- [ ] **Шаг 5. Список не голосовавших и выбравших `?`/`☕`.** `EstimationStats::calculate()` возвращает
  только `total`/`counted`; список участников не формируется и в UI не показывается.
- [ ] **Шаг 6. Предложенное значение для участников.** `stats.suggestion` считается, но участникам
  (не владельцу) не показывается; у владельца лишь подсвечивается кнопка.
  Также спецификация здесь противоречива: шаг 6 говорит о ближайшем к среднему, шаг 7 — к медиане;
  реализовано по шагу 7 (медиана).
- [ ] **Нечисловая шкала: распределение голосов.** Бэкенд считает `distribution`, фронтенд показывает
  только моду.
- [ ] **5а. «Нет голосов».** Явного сообщения нет: при пустом раунде выводится «Чаще всего выбирали: —»
  даже для числовой шкалы.
- [ ] **7б. Фиксация итога позже.** Кнопки фиксации есть только в блоке «Результат», который показывает
  один последний завершённый раунд. Если владелец запустил раунд по другой задаче, зафиксировать
  итог по предыдущей (статус `estimating`, `final_estimate = null`) через UI уже нельзя —
  нет просмотра результатов/фиксации на уровне конкретной задачи. Истории раундов в UI тоже нет.
- [ ] **7а. «Переголосовать».** Отдельной кнопки нет; работает через «Начать оценку» у задачи.
  Функционально достаточно, но не соответствует описанному UI.
- [ ] **Блокировка при завершении.** `FinishRoundHandler` идемпотентен по проверке статуса в памяти,
  но без `SELECT ... FOR UPDATE` / Redis-lock из примечаний к реализации. При одновременном завершении
  воркером и владельцем возможна гонка (двойная вставка `votes` упрётся в unique-constraint и даст 500).

Завершение по таймеру и вручную, перенос голосов в PostgreSQL, очистка Redis, среднее/медиана/мода/
разброс, `round.finished`, фиксация итога владельцем с проверкой шкалы, `task.estimated`,
ленивое завершение при сбое воркера — ✅.

## Общие замечания (README usecases)

- Тестов нет вообще (см. CLAUDE.md) — ни одного сценария нельзя проверить автоматически.
- Realtime реализован через Redis Stream + SSE вместо Mercure/WebSocket из спецификации — функционально
  эквивалентно, расхождение только в примечаниях к реализации.
- Ключ `room:{id}:active_round` в Redis (UC-06/UC-08) не используется: активный раунд определяется по
  PostgreSQL. На поведение не влияет.
