# UC-04. Создание задачи на оценку

Владелец добавляет в комнату задачу, которую предстоит оценить.

## Акторы
- Владелец комнаты (основной)
- Участники (получают уведомление)
- Система

## Предусловия
- Комната создана (UC-03), пользователь является её владельцем.

## Триггер
Владелец нажимает «Добавить задачу» на странице комнаты.

## Основной сценарий
1. Владелец вводит название задачи и, опционально, описание и внешнюю ссылку (например, на тикет в трекере).
2. Система проверяет: название от 1 до 200 символов, описание до 5000 символов, ссылка — корректный URL.
3. Система сохраняет задачу в комнате со статусом «не оценена» и помещает её в конец списка.
4. Система уведомляет участников о новой задаче в реальном времени.

## Альтернативные сценарии
- **2а. Невалидные данные.** Система показывает ошибки у полей.
- **Редактирование.** Владелец может изменить название/описание задачи, пока по ней нет активного раунда.
- **Удаление.** Владелец может удалить задачу, если по ней нет активного раунда. Завершённые раунды по ней удаляются вместе с задачей.
- **Изменение порядка.** Владелец перетаскивает задачи в списке; порядок сохраняется.
- **Не владелец.** Участник без прав владельца не видит кнопки добавления; при прямом запросе к API получает 403.

## Постусловия
- В комнате появилась задача со статусом «не оценена», доступная для запуска оценки (UC-06).

## Примечания к реализации
- PostgreSQL: `tasks` (id, room_id, title, description, external_url, position, status: `pending` | `estimating` | `estimated`, final_estimate, created_at).
- Realtime-события `task.created`, `task.updated`, `task.deleted`, `task.reordered`.
