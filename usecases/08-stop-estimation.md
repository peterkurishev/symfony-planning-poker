# UC-08. Остановка оценки по таймеру

Система автоматически завершает раунд по истечении времени, раскрывает голоса и вычисляет статистику; владелец фиксирует итоговую оценку.

## Акторы
- Система (таймер) — основной
- Владелец комнаты (фиксирует итог, может остановить досрочно)
- Участники (видят результаты)

## Предусловия
- В комнате есть активный раунд (UC-06).

## Триггер
Наступил дедлайн раунда.

## Основной сценарий
1. Система по наступлении дедлайна получает отложенное сообщение о завершении раунда.
2. Система проверяет, что раунд ещё активен (не был остановлен вручную ранее).
3. Система переводит раунд в статус `finished`, фиксирует время завершения.
4. Система переносит голоса из временного хранилища в базу данных и очищает временное хранилище.
5. Система вычисляет статистику (правила — в UC-05):
   - для числовой шкалы: среднее арифметическое (с округлением до 1 знака) и медиану по числовым голосам;
   - для нечисловой: распределение голосов и моду;
   - список участников, которые не голосовали или выбрали `?`/`☕`.
6. Система уведомляет всех участников: раунд завершён, показываются все голоса поимённо, среднее, медиана, ближайшее значение шкалы к среднему.
7. Владелец выбирает итоговую оценку: система предлагает по умолчанию ближайшее к медиане значение шкалы, владелец может выбрать любое другое значение шкалы.
8. Система сохраняет итоговую оценку у задачи, переводит задачу в статус «оценена» и уведомляет участников.

## Альтернативные сценарии
- **Ручная остановка владельцем.** Владелец нажимает «Остановить» до дедлайна (например, после уведомления, что все проголосовали). Система выполняет шаги 3–8 немедленно; отложенное сообщение таймера при получении обнаруживает, что раунд уже завершён, и ничего не делает.
- **2а. Раунд уже завершён.** Система игнорирует сообщение таймера.
- **5а. Никто не проголосовал.** Система показывает «нет голосов», статистика не считается; владелец может запустить раунд повторно (UC-06) или ввести оценку вручную.
- **5б. Голоса сильно расходятся.** Если разброс велик (например, максимум и минимум отстоят более чем на 2 позиции шкалы), система подсвечивает это и предлагает обсудить и переголосовать.
- **7а. Повторный раунд.** Владелец вместо фиксации итога нажимает «Переголосовать»; система запускает новый раунд по той же задаче (UC-06), предыдущий раунд сохраняется в истории.
- **7б. Владелец отложил решение.** Итог не зафиксирован, задача остаётся в статусе «оценивается» с результатами последнего раунда; владелец может зафиксировать итог позже.
- **Сбой воркера.** Если сообщение таймера не обработано вовремя, при любом запросе к комнате система сверяет `deadline_at` с текущим временем и при просрочке завершает раунд синхронно (ленивое завершение).

## Постусловия
- Раунд в статусе `finished`, голоса сохранены в базе.
- Участники видят раскрытые голоса и статистику.
- После шага 8 у задачи есть итоговая оценка, статус «оценена».

## Примечания к реализации
- Symfony Messenger: транспорт на Redis или Doctrine, `DelayStamp(duration_sec * 1000)`; обработчик `FinishRoundHandler` идемпотентен (проверка статуса под блокировкой `SELECT ... FOR UPDATE` либо Redis-lock).
- PostgreSQL: `votes` (round_id, user_id, value, created_at); `tasks.final_estimate`, `tasks.status = estimated`.
- Redis: удалить `round:{id}:votes` и `room:{id}:active_round` после переноса.
- Realtime-события: `round.finished` (голоса, статистика), `task.estimated` (итог).
- Расчёт медианы: сортировка числовых голосов, среднее двух центральных при чётном количестве.
